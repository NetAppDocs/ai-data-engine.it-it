= Requisiti di AI Data Engine
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Prima di implementare AI Data Engine (AIDE), verifica i requisiti di rete, Kubernetes, dimensionamento e sistema operativo per il tuo ambiente. Per un'implementazione a nodo singolo, ti basta fornire una VM Linux e AI Data Engine esegue automaticamente il provisioning di tutto il resto. Per un'implementazione multi-node, usa il tuo cluster Kubernetes.

|===

| AI Data Engine per ONTAP (SMB) | 139, 445 | TCP/UDP | Nello storage | Accesso alla sorgente dati SMB

| AI Data Engine per i servizi NetApp, il registro container e la CDN | 443 | TCP | outbound | HTTPS: lo script di installazione viene scaricato da una CDN, l'immagine del container e il chart Helm vengono scaricati da ECR e il catalogo dei componenti viene scaricato da S3

[[flexible-sizing-guidelines]]
[[flexible-sizing-single-node]]
=== Linee guida di dimensionamento flessibili

<<single-node-vm-sizes,Configurazioni piccole, medie e grandi>>Si tratta di valori di riferimento consigliati per una finestra di scansione iniziale di tre o quattro giorni, non limiti rigidi imposti dal software.

Che cosa determina i consigli per il dimensionamento::
+
--
* *Numero totale di file e directory*: Il numero totale di oggetti da catalogare è il fattore determinante per i requisiti di elaborazione e archiviazione. Un numero maggiore di oggetti richiede proporzionalmente più memoria, CPU e spazio di archiviazione.
* *Struttura delle directory*: L'utilizzo delle risorse varia in base alla profondità di annidamento delle directory e alla distribuzione dei file tra condivisioni e volumi. Strutture profondamente annidate o altamente frammentate possono richiedere più risorse rispetto allo stesso numero di file in una gerarchia più piatta.
* *Throughput di scansione richiesto*: La velocità di completamento iniziale del catalogo è direttamente correlata all'allocazione di CPU e memoria. Un dimensionamento inferiore a quello consigliato riduce il throughput e prolunga la finestra temporale della scansione iniziale.
* *Performance dello storage*: è vivamente consigliato uno storage dalle performance elevate. L'indicizzazione dei metadati e l'elaborazione degli eventi richiedono IOPS e throughput costanti proporzionali alle dimensioni dell'implementazione.


--
Cosa succede se sottodimensioni o superi la dimensione implementata::
+
--
Ogni configurazione è ottimizzata per uno specifico numero di file e una determinata velocità di scansione. Se il tuo ambiente supera i limiti supportati dalla configurazione, potresti riscontrare quanto segue:

* *Durata estesa del catalogo iniziale*: una minore potenza di calcolo riduce il numero di oggetti sottoposti a scansione al giorno. Ad esempio, un'implementazione destinata a 3 miliardi di oggetti ma con provisioning di dimensioni inferiori può richiedere molto più tempo rispetto all'obiettivo di tre o quattro giorni.
* *Throughput di acquisizione continuo ridotto*: i nuovi eventi relativi ai file e gli aggiornamenti incrementali delle scansioni vengono elaborati più lentamente in caso di carico prolungato.
* *Scansione bloccata*: i componenti di AI Data Engine sono configurati in base alle dimensioni del deployment. Quando l'ambiente supera significativamente tali dimensioni, la scansione potrebbe bloccarsi anziché semplicemente rallentare. Per verificare la presenza di carichi di lavoro non integri e di vincoli delle risorse, consulta link:../administer/monitor-deployment-health.html["Monitora lo stato di integrità della distribuzione e analizza i problemi"].
* *Rischio di capacità dello storage*: una capacità dello storage insufficiente rispetto al numero totale di oggetti può spingere l'indice dei metadati verso le soglie di capacità. Contatta il Supporto NetApp per pianificare un'espansione dello storage.


--
Supera le dimensioni consigliate::
+
--
I componenti di AI Data Engine sono configurati per le dimensioni che implementi, quindi l'aggiunta di vCPU, memoria o storage alla VM host non aumenta automaticamente la capacità. Se il numero di file o le prestazioni di cui hai bisogno superano le dimensioni che hai implementato, contatta NetApp Support per ridimensionare la configurazione.


NOTE: Una distribuzione a nodo singolo non supporta l'alta disponibilità né lo scale-out orizzontale. Se il tuo ambiente supera costantemente i 3 miliardi di file o se hai bisogno di alta disponibilità e tolleranza ai guasti, distribuisci invece link:deploy-aide-multi-node.html["Implementazione multi-nodo di AIDE"].

--

<<multi-node-sizes,Configurazioni piccole, medie e grandi>>sono configurazioni di base consigliate del cluster per una finestra di scansione iniziale di tre o quattro giorni, non limiti di capacità rigidi imposti dal software. Che cosa determina i consigli per il dimensionamento::
+
--
* *Numero totale di file e directory*: Il numero totale di oggetti è il fattore determinante per i requisiti di storage e di elaborazione. Gli ambienti più grandi richiedono nodi cluster aggiuntivi per distribuire il carico di elaborazione e mantenere le prestazioni.
* *Replica ad alta disponibilità*: le implementazioni multi-nodo consentono la replica dei dati tra i nodi per impostazione predefinita, garantendo la tolleranza ai guasti. La replica aumenta i requisiti totali di storage e memoria rispetto a un'implementazione equivalente a nodo singolo.
* *Numero di nodi e distribuzione del carico di lavoro*: il throughput di elaborazione e la capacità totale del catalogo scalano con il numero di nodi nel cluster. I nodi aggiuntivi distribuiscono sia il carico di lavoro di indicizzazione sia la capacità di archiviazione nell'intero cluster.
* *Throughput di scansione richiesto*: l'allocazione di CPU e memoria a livello di cluster determina la velocità di scansione giornaliera e la rapidità di completamento del catalogo iniziale.
* *Performance dello storage per nodo*: si consiglia vivamente di utilizzare uno storage dalle performance elevate su ciascun nodo e la capacità totale del cluster aumenta proporzionalmente al numero di nodi.


--
Cosa succede se sottodimensioni o superi la dimensione implementata::
+
--
Ogni configurazione è ottimizzata per uno specifico numero di file e una determinata velocità di scansione. Se il tuo ambiente supera i limiti supportati dalla configurazione, potresti riscontrare quanto segue:

* *Durata iniziale del catalogo estesa*: un numero inferiore di nodi o una riduzione delle risorse per nodo comportano un throughput inferiore, estendendo proporzionalmente la finestra iniziale del catalogo.
* *Aumento della latenza di elaborazione in condizioni di carico di picco*: una quantità insufficiente di memoria nel cluster può causare una latenza di elaborazione elevata durante i periodi di acquisizione di grandi volumi di dati.
* *Scansione bloccata*: i componenti di AI Data Engine sono configurati in base alle dimensioni del deployment. Quando l'ambiente supera significativamente tali dimensioni, la scansione potrebbe bloccarsi anziché semplicemente rallentare. Per verificare la presenza di carichi di lavoro non integri e di vincoli delle risorse, consulta link:../administer/monitor-deployment-health.html["Monitora lo stato di integrità della distribuzione e analizza i problemi"].
* *Rischio relativo alla capacità di storage*: una capacità di storage del cluster insufficiente per il numero di oggetti previsto può spingere l'indice dei metadati verso le soglie di capacità. Contatta NetApp Support per pianificare un'espansione dello storage.


--
Supera le dimensioni consigliate::
+
--
Il ridimensionamento orizzontale di un cluster multi-node esistente non è supportato. L'aggiunta di nodi worker o di nodi di storage dedicati non aumenta automaticamente la capacità di elaborazione delle scansioni, di acquisizione degli eventi o del catalogo. Se il tuo ambiente supera le dimensioni distribuite oppure hai bisogno di una maggiore capacità di elaborazione delle scansioni o di acquisizione degli eventi, contatta NetApp Support o il tuo referente NetApp per pianificare la modifica.


NOTE: Per scalare oltre sei miliardi di file, contatta il tuo NetApp rappresentante per ricevere indicazioni sul dimensionamento dei nodi e una scalabilità personalizzata.

[[kerberos-and-active-directory-requirements]]
[[kerberos-ad-requirements]]
== Requisiti di Kerberos e Active Directory

Esamina questi requisiti prima di eseguire la scansione delle condivisioni SMB/CIFS con autenticazione Kerberos o di mappare gli ID utente e di gruppo NFS ai nomi di Active Directory. I requisiti relativi alla sincronizzazione dell'ora, al DNS e al pacchetto host si applicano solo a Kerberos. AIDE è un client Kerberos: si autentica nel tuo Kerberos key distribution center (KDC) esistente e non funge da server Kerberos.



[[time-synchronization]]
=== Sincronizzazione temporale

L'autenticazione Kerberos non riesce quando gli orologi dei nodi AIDE e del KDC differiscono di oltre la differenza di orario consentita. Per impostazione predefinita, Active Directory consente una differenza massima di cinque minuti.

Verifica quanto segue:

* Il protocollo NTP (Network Time Protocol) è attivo su tutti i nodi AIDE.
* I nodi AIDE utilizzano una sorgente oraria sincronizzata con i controller di dominio.




[[dns]]
=== DNS

Soddisfa i seguenti requisiti DNS:

* Ogni nodo AIDE può risolvere il file server e il KDC tramite nome di dominio completo (FQDN).
* Se configuri i nodi per utilizzare il tuo DNS server Active Directory, tale server deve anche risolvere i nomi esterni. In caso contrario, AIDE non può raggiungere gli endpoint elencati in <<outbound-internet-access,Accesso Internet outbound>>.
* Se modifichi le impostazioni DNS in una distribuzione multi-node, configura il DNS server di Active Directory come unico name server su ogni nodo. La risoluzione dei nomi nel cluster seleziona casualmente uno dei name server elencati, quindi un name server che non riesce a risolvere i nomi di Active Directory causa errori intermittenti.


Per modificare le impostazioni DNS, consulta "Correggere la risoluzione dei nomi" in link:../administer/configure-kerberos-smb-single-node.html#fix-name-resolution["Configurare Kerberos per le condivisioni SMB/CIFS in una distribuzione a nodo singolo"] o link:../administer/configure-kerberos-smb-multi-node.html#fix-name-resolution["Configura Kerberos per le condivisioni SMB/CIFS in una distribuzione multi-node"].



[[host-packages]]
=== Pacchetti host

[cols="1,3"]
|===
| Distribuzione | Pacchetti richiesti 


| Nodo singolo | Strumenti client Kerberos: `krb5-user` su Ubuntu o `krb5-workstation` su RHEL. Il programma di installazione installa automaticamente `cifs-utils` per supportare l'accesso SMB autenticato con Kerberos. 


| Multinodo | `cifs-utils` su ogni nodo e strumenti client Kerberos e un client NFS sull'host in cui crei e testi il keytab. 
|===
 `cifs-utils` è richiesto su ogni nodo AIDE solo per la scansione SMB/CIFS basata su Kerberos. Il programma di installazione per nodo singolo lo installa. In una distribuzione multi-node, lo installi su ogni nodo. La scansione Kerberos di una CIFS share non riesce se  `cifs-utils` manca su un nodo.



[[active-directory-attributes-for-nfs]]
=== Attributi di Active Directory per NFS

Per risolvere gli ID utente e di gruppo NFS in nomi di Active Directory, gli attributi  `uidNumber` e  `gidNumber` devono essere popolati e replicati nel Global Catalog se AIDE lo interroga. Consulta link:../administer/configure-ad-nfs.html["Configura la mappatura delle identità di Active Directory per NFS"].
